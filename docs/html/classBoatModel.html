It loads the iges file and extract different curves, surfaces and points. Following is the brief explanation of what this function is doing;.

  • Inputs to this function are igesFileName, scale, displacement, assigned_sink, assigned_trim, back_keel_length, front_keel_length, and middle_keel_length. Check classMembers.md for more details of these input variables.
  • Read hull's shape from iges file using dealii::OpenCASCADE::read_iges() functionality and returns a TopoDS_Shape object. Note that only half (symmetric) geometry is provided in iges file and all further operations are considered on the same fact.
  • Each face of the hull is processed in the loop to determine if its orientation needs to be changed. (As per WaveBEM code, the direction of face is kept inwards)
  • Creating a mirrored version of the hull along the Y-axis
  • Now, if displacement of the hull is non-zero, we perform the translation movement of hull in z-direction. We first calculate hydrostatic sinkage as per weight of water displacement (in kg) using BoatModel::compute_hydrostatic_sink() function, which uses Newton Raphson iterative method to find correct sinkage to balance displacement weight, and then translate the hull vertically. It also updates boatWetSurface area.
  • Calculate boat_mass (mass of the boat) by using hydrostatic force in z-direction
  • Compute the longitudinal position of pressure center: we'll place the the hull baricenter there. Perform the rotation and translation transformation according to assigned_sink and assigned_sink. Note that till this point, hull body is placed in requested position though rigid body motion of hull is NOT considered. That part will be considered in free surface initialization section.
  • Now we will extract different curves/edges/points from hull's iges file. Starting with extracting TopoDS_Edge keel_edge (intersection of TopoDS_Shape with x-z plane).
  • Then we extract transom edges. Start with any side, let's say TopoDS_Edge right_transom_edge, then mirror it to get left_transom_edge.
  • Next we extract the undisturbed waterline edges as TopoDS_Edge, both right_undist_water_line and left_undist_water_line (intersection of TopoDS_Shape with x-y plane and then mirror it to get other one)
  • Convert TopoDS_Shape right_undist_water_line and left_undist_water_line into Handle(Geom_Curve) right_undisturbed_waterline_curve and left_undisturbed_waterline_curve. Geom_Curve is needed to calculate various geometric properties of that curve which are absent in TopoDS_Shape.
  • Calculate the slope ($dy/dx$) at rear end point of either of right_undisturbed_waterline_curve/left_undisturbed_waterline_curve. It will be helpful in creating wakeline curves.
  • keel_edge, left_transom_edge, and right_transom_edge is also converted into Handle(Geom_Curve) equiv_keel_bspline, left_transom_bspline and right_transom_bspline respectively. Using these transom bsplines Geom_Curve, we obtain the intersection point PointCenterTransom of both transom.
  • Calculate equiv_keel_bspline intersection with x-y plane and find the number of intersecting points npoints.
    • If the npoints==2, then it means transom is NOT present is_transom=false and those points are stored as front and rear points of waterline as gpFront and gpBack respectively. we construct two Handle(Geom_Curve) left_wake_bspline, and right_wake_bspline wakeline curves, whose end points are gpBack and (50*boatWetLength, 0.0, 0.0). boatWetLength is calculated using the distance between x-coordinate of gpFront and gpBack.
    • If the npoints==1, then transom is present is_transom=true. In this case, gpBack is PointCenterTransom (keel-transom intersection point). Along with two wakeline curves mentioned above, we create two more wakelines using junction point, where junction is the point where tangent (or slope $dy/dx$ calculated above) intersects x-axis. So, first two wakelines are from junction point to far point (50*boatWetLength, 0.0, 0.0) and second two wakelines are from transomLeft (and transomRight) point to junction point. boatWetLength here is considered as distance between x-coordinate of transomLeft (or transomRight) and gpFront. Note that for each side (left/right), both wakelines are combined into left_wake_bspline and right_wake_bspline Geom_Curve object.
  • define the waterline arclength projection object. DOCUMENTATION INCOMPLETE!
  • Create a normal projection on surface objects defined using custom defined OpenCASCADE utility named NormalProjection, to project any point normally on the hull's surface. boat_surface_right is for whole right hull surface and boat_surface_left is for left hull surface.
  • Create a axis projection object defined using custom defined OpenCASCADE utility named AxisProjection. It projects any point along the y direction horizontally on hull's surface. Again, one is created for right boat_water_line_right and one for left boat_water_line_left.
  • Similarly, create a AxisProjection object (named undist_water_surf) which projects any point on undisturbed free surface along the vertically z direction.
  • Create a projection objects based on custom defined OpenCASCADE utility named ArclengthProjection which projects any point on the defined curves using arclengths. water_line_right object uses right_undist_water_line and water_line_leftobject uses left_undist_water_line. Same thing is done for both transom curves and their arclength projection objects are stored as boat_transom_left and boat_transom_right.
  • For keel edge, we define ArclengthProjection and NormalProjection objects as boat_keel and boat_keel_norm respectively.
  • Extracting end and mid-points at top and bottom water lines.
