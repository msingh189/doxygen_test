boat_model.start_iges_model(): It loads the iges file and extract different curves, surfaces and points. Following is the brief explanation of what this function is doing;

  • Inputs to this function are igesFileName, scale, displacement, assigned_sink, assigned_trim, back_keel_length, front_keel_length, and middle_keel_length. Check classMembers.md for more details of these input variables.
  • Read hull's shape from iges file using dealii::OpenCASCADE::read_iges() functionality and returns a TopoDS_Shape object. Note that only half (symmetric) geometry is provided in iges file and all further operations are considered on the same fact.
  • Each face of the hull is processed in the loop to determine if its orientation needs to be changed. (As per WaveBEM code, the direction of face is kept inwards)
  • Creating a mirrored version of the hull along the Y-axis
  • Now, if displacement of the hull is non-zero, we perform the translation movement of hull in z-direction. We first calculate hydrostatic sinkage as per weight of water displacement (in kg) using BoatModel::compute_hydrostatic_sink() function, which uses Newton Raphson iterative method to find correct sinkage to balance displacement weight, and then translate the hull vertically. It also updates boatWetSurface area.
  • Calculate boat_mass (mass of the boat) by using hydrostatic force in z-direction
  • Compute the longitudinal position of pressure center: we'll place the the hull baricenter there. Perform the rotation and translation transformation according to assigned_sink and assigned_sink. Note that till this point, hull body is placed in requested position though rigid body motion of hull is NOT considered. That part will be considered in free surface initialization section.
  • Now we will extract different curves/edges/points from hull's iges file. Starting with extracting TopoDS_Edge keel_edge (intersection of TopoDS_Shape with x-z plane).
  • Then we extract transom edges. Start with any side, let's say TopoDS_Edge right_transom_edge, then mirror it to get left_transom_edge.
  • Next we extract the undisturbed waterline edges as TopoDS_Edge, both right_undist_water_line and left_undist_water_line (intersection of TopoDS_Shape with x-y plane and then mirror it to get other one)
  • Convert TopoDS_Shape right_undist_water_line and left_undist_water_line into Handle(Geom_Curve) right_undisturbed_waterline_curve and left_undisturbed_waterline_curve. Geom_Curve is needed to calculate various geometric properties of that curve which are absent in TopoDS_Shape.
  • Calculate the slope ($dy/dx$) at rear end point of either of right_undisturbed_waterline_curve/left_undisturbed_waterline_curve. It will be helpful in creating wakeline curves.
  • keel_edge, left_transom_edge, and right_transom_edge is also converted into Handle(Geom_Curve) equiv_keel_bspline, left_transom_bspline and right_transom_bspline respectively. Using these transom bsplines Geom_Curve, we obtain the intersection point PointCenterTransom of both transom.
  • Calculate equiv_keel_bspline intersection with x-y plane and find the number of intersecting points npoints.
    • If the npoints==2, then it means transom is NOT present is_transom=false and those points are stored as front and rear points of waterline as gpFront and gpBack respectively. we construct two Handle(Geom_Curve) left_wake_bspline, and right_wake_bspline wakeline curves, whose end points are gpBack and (50*boatWetLength, 0.0, 0.0). boatWetLength is calculated using the distance between x-coordinate of gpFront and gpBack.
    • If the npoints==1, then transom is present is_transom=true. In this case, gpBack is PointCenterTransom (keel-transom intersection point). Along with two wakeline curves mentioned above, we create two more wakelines using junction point, where junction is the point where tangent (or slope $dy/dx$ calculated above) intersects x-axis. So, first two wakelines are from junction point to far point (50*boatWetLength, 0.0, 0.0) and second two wakelines are from transomLeft (and transomRight) point to junction point. boatWetLength here is considered as distance between x-coordinate of transomLeft (or transomRight) and gpFront. Note that for each side (left/right), both wakelines are combined into left_wake_bspline and right_wake_bspline Geom_Curve object.
  • define the waterline arclength projection object. DOCUMENTATION INCOMPLETE!
  • Create a normal projection on surface objects defined using custom defined OpenCASCADE utility named NormalProjection, to project any point normally on the hull's surface. boat_surface_right is for whole right hull surface and boat_surface_left is for left hull surface.
  • Create a axis projection object defined using custom defined OpenCASCADE utility named AxisProjection. It projects any point along the y direction horizontally on hull's surface. Again, one is created for right boat_water_line_right and one for left boat_water_line_left.
  • Similarly, create a AxisProjection object (named undist_water_surf) which projects any point on undisturbed free surface along the vertically z direction.
  • Create a projection objects based on custom defined OpenCASCADE utility named ArclengthProjection which projects any point on the defined curves using arclengths. water_line_right object uses right_undist_water_line and water_line_leftobject uses left_undist_water_line. Same thing is done for both transom curves and their arclength projection objects are stored as boat_transom_left and boat_transom_right.
  • For keel edge, we define ArclengthProjection and NormalProjection objects as boat_keel and boat_keel_norm respectively.
  • Extracting end and mid-points at top and bottom water lines.

2.2.1 <tt>LineSmoothing</tt> class

Smooth all dofs in euler_vector for which smoothing_dofs is set to true. Exceptions are thrown if the points are not located on the Geometry curve. The parameter base_point_id, identifies the 3 dofs associated with the base point, which is the one left untouched. All other points are moved proportionally to their arclength distance from the base point. The driving point id is given by driving_point_id.

Initialization - LineSmoothing constructor:

  • Input to this constructor is as follows:
    • Takes a reference to euler displacement vector euler_vector which is smoothing_map_points. The euler_vector is interpreted as a collection of triples associated with the displacement of the nodes of the mesh, like the one which is used in MappingQEulerian.
    • Reference curve Handle(Geom_Curve) which is stored as ref_curve.
    • A pointer to TopLoc_Location *curr_loc location for coordinate system transformation whose reference is stored as curr_location.
    • reference to deal.II DoFHandler stored as dh.
    • std::vector of booleans stored in smoothing_dofs.
    • base point and moving point indices stored as unsigned int in b_point_id and d_point_id.
    • tolerance.
  • This constructor apart from above mentioned variables, creates a copy of ref_curve into curve and a projection. If curr_location is NULL, use identity transformation, otherwise use *curr_location and store this pointer to ref_location and used_location.
  • Calls update_reference() to map degrees of freedom (DoFs) onto support points.

Reference Update update_reference():

  • First, it converts the Geom_Curve into geometry adaptor BRepAdaptor_Curve to store the curve parameter value of base point in occ_base_t.
  • Then we loop over all the nodes, the points for which smoothing_dofs==true (or all point currently lying b/w base and moving point), we store the indices in an increasing order of its distance from base point, in smoothing_list which is a std::map mapping std::pair of parameter value and distance value to the corresponding indices. The distance is calculated using curve parameter values.
  • Compute the reference support points (this is local to this class only).
  • Calculate the reference length of the curve which will the highest value of curve distance value in smoothing_list.
  • Re-initializes the deal.II Vectors<double> lengths_before_smoothing, lengths_after_smoothing, fixed_length_ratios, and std::vector node_indices. Also updates the node_indices and fixed_length_ratios based on smoothing_list.

Curve Smoothing smooth(bool maintain_on_original_curve):

  • Perform the actual smoothing. Notice that the argument decides whether or not the moving point is projected to the original curve. If this is not the case, then all points are maintained in their current location, a new curve is computed which passes through all current points, and their smoothing is computed according to their original location.
  • Updates the driving point location based on the euler displacement vector euler_vector.
  • If maintain_on_original_curve is enabled, ensures the curve stays constrained to the original. A horizontal plane is created ($z=z_{drivingPnt}$) and its intersection with curve is done to obtain driving point projection on the curve.
  • If maintain_on_original_curve is disabled, we first get all the points on this un-smoothened curve, update it with euler_vector and interpolate it to obtain the curve based on these new points. Since curve is changed, occ_base_t is also updated.
  • Based on the argument, whatever curve we retain/obtain, we create a geometry adaptor of the same, obtain the occ_driving_t driving point curve parameter. Also obtain the total length of the curve using occ_base_t and occ_driving_t.
  • Projects smoothing points onto the new curve using fixed_length_ratios and updates the displacement vector euler_vector accordingly.

2.2.2 <tt>SurfaceSmoothing</tt> class

Smooth all dofs in euler_vector, by maintaining the boundary dofs at their position.

Initialization - SurfaceSmoothing constructor:

  • Input to this constructor is as follows:
    • Takes a reference to euler displacement vector euler_vector which is smoothing_map_points. The euler_vector is interpreted as a collection of triples associated with the displacement of the nodes of the mesh, like the one which is used in MappingQEulerian.
    • Again takes a reference to curvature vector curvature_vector of each nodes. It is deal.II Vector<double> containing right hand side for smoothing beltrami problem.
    • reference to deal.II DoFHandler stored as dh.
    • Mapping should be parent of MappingQEulerian, in some sense. It is used to compute all integrals, which means it is required to return points in real space.
  • You should also call update_reference() the first time you use this class, otherwise exceptions will be thrown.

Reference Update update_reference():

  • Whenever the underlying dh changes, you should call this function to update the internal vectors, matrices, sparsity pattern, and constraints.
  • It also updates the boundary_dofs() which is set to true for the all the nodes lying on the surface of boat, when dh is updated.

  • perform_water_line_nodes_projection(): Projects all the points on the current waterline to the actual waterlines and also calculates the mean curvature & normal vector at these points.

  • perform_surface_projection(): Projects the current points on the hull's surface on the actual hull's surface along with updating the mean curvature and normal vectors.
    • We first update the vector of mesh normals at node, then we update the support points and reference points using update_support_points().

  • vector_constraints.distribute(map_points): After calculating all the displacement of all nodes possible in map_points, we set all constrained dofs to values so that constraints are satisfied using distribute() functionality of AffineConstraints.

free_surface.differential_components(): It is responsible for setting up the classification of dofs. The classification divides DoFs into: (1) Differential Components (diff_comp): DoFs governed by differential equations, and (2) Algebraic Components (alg_comp): DoFs governed by algebraic constraints.

  • An identification of the differential components. This sets diff_comp to be 1 if the corresponding variable is a differential component, zero otherwise. Just opposite for alg_comp.
  • There is another type of classfication as well, representing the system components (sys_comp): Categorization of DoFs into different physical classifications, such as
    • 0: X algebraic (horizontal coords, vertical constrained coords, vertical coords not on free surface)
    • 1: X differential (vertical non constrained free surface coords)
    • 2: phi algebraic (non constrained nodes, on neumann boundaries)
    • 3: phi differential (non constrained nodes on dirichlet pressure boundaries / free surface)
    • 4: dphi/dn algebraic (on boat or inflow coming from L2 projection)
    • 5: dphi/dn algebraic (constrained nodes)
    • 6: phi algebraic (constrained nodes)
    • 7: dphi/dn algebraic (non constrained nodes on water/pressure coming from BEM solution)
    • 8: X algebraic (x coordinate on free surface)
    • 9: X algebraic (y coordinate on free surface)
    • 10: phi algebraic (imposed equal to water counterpart on pressure side of pressure water interface)
    • 11: rigid body velocities and displacements (differential)
  • For nodes that are identified as part of the free surface (water), the vertical coordinate (Z) is marked as differential, while the horizontal coordinates (X, Y) are algebraic. This reflects the fact that the free surface's vertical motion is dictated by physics (differential equation), while horizontal movements may be constrained algebraically.
  • If a node lies on a sharp edge or transom_on_water, additional constraints apply. The presence of the transom affects the boundary conditions and hence changes whether a DoF is treated as algebraic or differential.
  • Jacobian Sparsity Pattern (jacobian_sparsity_pattern): Once the DoFs are classified, the function also initializes the jacobian_sparsity_pattern. The sparsity pattern ensures that only relevant interactions between DoFs are accounted for, improving computational performance.

2.4.1 Testing the laplace solution

We create the two deal.II Vector<double> bem_phi and bem_dphi_dn to store the potential and its normal gradient values at all nodes. We also make copy of num_dom.surface_nodes and num_dom.other_nodes for backup. We compute the normals at node.

Then we apply the boundary conditions with neumann bc at hull's surface, free surface, inflow boundary and dirichlet bc of zero potential at other boundaries. We apply the neumann bc at nodes present at water surface, boat surface & inflow boundary, and homogenous dirichlet bc at all other nodes of remaining boundaries. Also, for dirichlet bc, we store 1 in num_dom.surface_nodes and 0 in num_dom.other_nodes & just opposite for neumann bc. We also create an another deal.II vector bem_bc which acts a temporary rhs vector tmp_rhs for BEMProblem class.

We solve the laplace problem using BEM, using bem.solve(). It provides two methods for solving laplace problem, either by Direct method or by FMA (Fast Multipole Algorithm).

Let's focus on assemble_system() function using Direct method. We start with assembling the matrix.

  • We initialize the neumann_matrix and dirichlet_matrix to zero.

  • Then we create a deal.II quadrature QGaussOneOverR for integrating $\frac{1}{R}f(x)$ on the reference element $[0,1]^2$, where $f$ is a smooth function without singularities, and $R$ is the distance from the point $x$ to the vertex $\xi$, given at construction time by specifying its index. Notice that this distance is evaluated in the reference element.
    ```cpp std::vector<dealii::QGaussOneOverR<2>> sing_quadratures_3d; for (unsigned int i=0; i<comp_dom.fe.dofs_per_cell; ++i) { sing_quadratures_3d.push_back(dealii::QGaussOneOverR<2>(comp_dom.singular_quadrature_order, comp_dom.fe.get_unit_support_points()[i], true)); } ```

    Last argument of constructor of QGaussOneOverR is set to true to factor out the singularity weight, meaning it should be specified by user.

  • Next, we initialize an FEValues object with the quadrature formula for the integration of the kernel in non singular cells. This quadrature is selected with the parameter file, and needs to be quite precise, since the functions we are integrating are not polynomial functions.
  • Unlike in FEM, if we use a collocation BEM, then in each assembly loop we only assemble the information that refers to the coupling between one degree of freedom (the degree associated with support point $i$) and the current cell. This is done using a vector of fe.dofs_per_cell elements, which will then be distributed to the matrix in the global row $i$. The following object will hold this information:
    ```cpp dealii::Vector<double> local_neumann_matrix_row_i(comp_dom.fe.dofs_per_cell); dealii::Vector<double> local_dirichlet_matrix_row_i(comp_dom.fe.dofs_per_cell); ```
  • Now that we have checked that the number of vertices is equal to the number of degrees of freedom, we construct a vector of deal.II points as support_points using DoFTools::map_dofs_to_support_points<dim-1, dim>( *comp_dom.mapping, comp_dom.dh, support_points) which will be used in the local integrations.
  • After doing so, we can start the integration loop over all cells, where we first initialize the FEValues object and get the quadrature points and normal vectors.

  • We then form the integral over the current cell for all degrees of freedom (note that this includes dof not located on the current cell, a deviation from the usual finite element integrals). The integral that we need to perform is singular if one of the local degrees of freedom is the same as the support point $i$. At the beginning of the loop we therefore check wether this is the case, and we store which one is the singular index: ```cpp for (unsigned int i=0; i<comp_dom.dh.n_dofs() ; ++i) { local_neumann_matrix_row_i = 0; local_dirichlet_matrix_row_i = 0;

    bool is_singular = false; unsigned int singular_index = dealii::numbers::invalid_unsigned_int;

    for (unsigned int j=0; j<comp_dom.fe.dofs_per_cell; ++j) { if (comp_dom.double_nodes_set[i].count(local_dof_indices[j]) > 0) { singular_index = j; is_singular = true; break; } } ```

  • We then perform the integral. If the index $i$ is not one of the local degrees of freedom, we simply have to add the single layer terms to the right hand side, and the double layer terms to the matrix: ```cpp if (is_singular == false) { for (unsigned int q=0; q<n_q_points; ++q) { const dealii::Point<dim> R = q_points[q] - support_points[i]; LaplaceKernel::kernels(R, D, s);

    for (unsigned int j=0; j<comp_dom.fe.dofs_per_cell; ++j) { local_neumann_matrix_row_i(j) += ((D*normals[q]) * fe_v.shape_value(j,q) * fe_v.JxW(q)); local_dirichlet_matrix_row_i(j) += (s * fe_v.shape_value(j,q) * fe_v.JxW(q)); } } }

    `` HereLaplaceKernel::kernels(R, D, s)takes the input singularity radial vector, calculate and stores the value of Green's function in doublesand its gradients as deal.II point inD.

  • Now we treat the more delicate case. If we are here, this means that the cell that runs on the $j$ index containssupport_point[i]. In this case both the single and the double layer potential are singular, and they require special treatment. <br> Whenever the integration is performed with the singularity inside the given cell, then a special quadrature formula is used that allows one to integrate arbitrary functions against a singular weight on the reference cell. Notice that singular integration requires a careful selection of the quadrature rules. In particular the deal.II library provides quadrature rules which are taylored for logarithmic singularities ([QGaussLog](https://www.dealii.org/current/doxygen/deal.II/classQGaussLog.html), [QGaussLogR](https://www.dealii.org/current/doxygen/deal.II/classQGaussLogR.html)), as well as for 1/R singularities ([QGaussOneOverR`](https://www.dealii.org/current/doxygen/deal.II/classQGaussOneOverR.html)).
  • Singular integration is typically obtained by constructing weighted quadrature formulas with singular weights, so that it is possible to write $\int_K f(x) s(x) dx = \sum_{i=1}^N w_i f(q_i)$ where $s(x)$ is a given singularity, and the weights and quadrature points $w_i,q_i$ are carefully selected to make the formula above an equality for a certain class of functions $f(x)$. In all the finite element examples we have seen so far, the weight of the quadrature itself (namely, the function $s(x)$), was always constantly equal to 1. For singular integration, we have two choices: we can use the definition above, factoring out the singularity from the integrand (i.e., integrating $f(x)$ with the special quadrature rule), or we can ask the quadrature rule to normalize the weights $w_i$ with $s(q_i)$: $\int_K f(x) s(x) dx = \int_K g(x) dx = \sum_{i=1}^N \frac{w_i}{s(q_i)} g(q_i)$.
  • We use this second option, through the factor_out_singular_weight parameter of both QGaussLogR and QGaussOneOverR. These integrals are somewhat delicate, especially in two dimensions, due to the transformation from the real to the reference cell, where the variable of integration is scaled with the determinant of the transformation. In two dimensions this process does not result only in a factor appearing as a constant factor on the entire integral, but also on an additional integral alltogether that needs to be evaluated: $\int_0^1 f(x)\ln(x/\alpha) dx = \int_0^1 f(x)\ln(x) dx - \int_0^1 f(x) \ln(\alpha) dx. $ This process is taken care of by the constructor of the QGaussLogR class, which adds additional quadrature points and weights to take into consideration also the second part of the integral. A similar reasoning should be done in the 3D case, since the singular quadrature is taylored on the inverse of the radius $r$ in the reference cell, while our singular function lives in real space.
  • In the 3D case everything is simpler because the singularity scales linearly with the determinant of the transformation. This allows us to build the singular two dimensional quadrature rules once and for all outside the loop over all cells, using only a pointer where needed.

  • Putting all this into a dimension independent framework requires a little trick. The problem is that, depending on dimension, we'd like to either assign a QGaussLogR<1> or a QGaussOneOverR<2> to a Quadrature<dim-1>. C++ doesn't allow this right away, and neither is a static_cast possible. However, we can attempt a dynamic_cast: the implementation will then look up at run time whether the conversion is possible and if that isn't the case simply return a null pointer. To be sure we can then add a safety check at the end. ```cpp const dealii::Quadrature<dim-1> singular_quadrature = (dim == 2 ? dynamic_cast<dealii::Quadrature<dim-1>>(new dealii::QGaussLogR<1>(comp_dom.singular_quadrature_order, dealii::Point<1>((double)singular_index), 1./cell->measure(), true)) : (dim == 3 ? dynamic_cast<dealii::Quadrature<dim-1>*>(&sing_quadratures_3d[singular_index]) : 0));

    Assert(singular_quadrature, dealii::StandardExceptions::ExcInternalError()); ``

  • Notice that in 1D integration this is not possible, since we need to know the scaling parameter for the quadrature, which is not known *apriori*. Here, the quadrature rule itself depends also on the size of the current cell. For this reason, it is necessary to create a new quadrature for each singular integration. Since we create it using the new operator of C++, we also need to destroy it using the dual of new:delete. This is done at the end, and only ifdim == 2. ``cpp if (dim==2) delete singular_quadrature; ```
  • Finally, we need to add the contributions of the current cell to the global matrix. ```cpp for (unsigned int j=0; j<comp_dom.fe.dofs_per_cell; ++j) { neumann_matrix(i,local_dof_indices[j]) += local_neumann_matrix_row_i(j); dirichlet_matrix(i,local_dof_indices[j]) += local_dirichlet_matrix_row_i(j); } ```

After assembling the neumann_matrix and dirichlet_matrix, we need to obtain the $\alpha$ matrix which contains the contribution of singularity node $i$ on itself. In other words, the second part of the integral operator is the term $\alpha(\mathbf{x}_i) \phi_j(\mathbf{x}_i)$. This in done using compute_alpha() function of BEMProblem class. Since we use a collocation scheme, $\phi_j(\mathbf{x}_i)=\delta_{ij}$ and the corresponding matrix is a diagonal one with entries equal to $\alpha(\mathbf{x}_i)$.
One quick way to compute this diagonal matrix of the solid angles, is to use the Neumann matrix itself. It is enough to multiply the matrix with a vector of elements all equal to -1, to get the diagonal matrix of the alpha angles, or solid angles. The result is then added back onto the system matrix object to yield the final form of the matrix. So the discretized boundary integral equation in matrix form for all nodes will be of form $[\alpha][\phi] + [N][\phi] = [D][q]$. So here we are making use of known solution in case of homogenous neumann bc at all boundaries for which any constant value of $\phi$ is used for calculation of solid angles.

Now, we compute the rhs vector of our linear system of equation using compute_rhs() of BEMProblem class, and store it into deal.II Vector system_rhs.

2.5 DAE Restart Procedure

free_surface.prepare_restart(0, y, yp): Method to make sure residual is null at each (re)start of the computation. y is deal.II vector which contains all the information of nodes displacement, velocity, potential, normal potential gradients and rigid hull motions *(This is same as dst in free_surface.initial_conditions() function)*. yp is deal.II vector which will contain the time derivative of all quantities present in y vector.

  • First of all, all yp for coordinates is to be set to zero: at restarts all is idle.
  • We create different deal.II ArrayView(s), extracted from y deal.II vector. We also extract all hull's rigid motion quantities, like displacement and velocity in translation and rotation motion. Also, we get the Vinf velocity.
  • Moves the rigid_motion_map_points vector (target positions) for the internal nodes of the hull mesh (all nodes except for the free surface ones). It iterates over all nodes and selects only internal hull nodes (excluding free surface). Using the original node position in the current hull configuration and transforming the node to the reference configuration, we extract rigid body motion parameters (linear displacement + rotation quaternion). Then it computes baricenter positions (reference and displaced). Constructs a rotation matrix from the quaternion and perform rotation and translation to get the final node position. Updates the num_dom.rigid_motion_map_points, storing the difference between reference and transformed positions.
  • Create a new eulerian vector full_map_points which accounts both the displacement field map_points and rigid_motion_map_points based on rigid motion. Initialize the residual vector nodes_pos_res to zero.
  • Creates a working copy of the displacement field working_map_points = num_dom.map_points for modifications. Loops through all nodes and applies constraints using num_dom.old_map_points, to ensure only certain mesh points move:
    • Water-edge nodes: Keep x and y fixed; z also fixed only if near inflow.
    • Boat nodes (not near water): Fully frozen.
    • Other nodes (not boat/water): Fully frozen.
    • Transom nodes in water: Fully frozen.
  • If the simulation just restarted, we set blend_factor = 0.0 (prevents mesh-induced velocity spikes). Otherwise, during normal operation, the blending factor smoothly increases from 0 to 1 using a sine function over half a remeshing period. After sufficient time (≥ 0.5 * remeshing_period), blend_factor = 1.0, and the mesh smoothing is fully applied. This is a stabilization technique to prevent unrealistic motion in the free surface mesh smoothing process.
  • Now we project right-side waterline nodes onto the boat surface without smoothing, ensuring nodes stay near the hull while respecting curvature. Projection happens only in the dominant direction (x or y). Same is repeated for left side. Similar smoothing projection is done for bow and stern nodes. We ensure that twin nodes of boat and far-field edge nodes have been moved by same amount.
  • We enforce the constraints on the new geometry assigned by the DAE solver. We set num_dom.map_points = working_map_points back. We update the support points and compute the normals at nodes.
  • Update the displacement of coordinates in y vector to subtact the rigid motion of ship hull. This might be due to account the rigid motion displacements separately.
  • Calculate potential gradients using compute_potential_gradients() and store the same in deal.II Vector complete_potential_gradients. Then we loop over all the water-boat interface nodes which are on water (except transom and end nodes) and make sure the boat nodes' velocity must be parallel to boat's surface. Similar process is done for bow and stern nodes.
  • Now we create a reference cell of [-1,1]x[-1,1] in local coordinates direction. Using this we try to assemble the different mass matrix for residual of non-linear system $F(\boldsymbol{
    {y} }, \boldsymbol{y}, t)=0$.
