◆ differential_components()

template<int dim>
dealii::Vector< double > & FreeSurface< dim >::differential_components
overridevirtual

Identification of the differential components. This has to be 1 if the corresponding variable is a differential component, zero otherwise.

It is responsible for setting up the classification of dofs. The classification divides DoFs into: (1) Differential Components (diff_comp): DoFs governed by differential equations, and (2) Algebraic Components (alg_comp): DoFs governed by algebraic constraints.

  • An identification of the differential components. This sets diff_comp to be 1 if the corresponding variable is a differential component, zero otherwise. Just opposite for alg_comp.
  • There is another type of classfication as well, representing the system components (sys_comp): Categorization of DoFs into different physical classifications, such as
    • 0: X algebraic (horizontal coords, vertical constrained coords, vertical coords not on free surface)
    • 1: X differential (vertical non constrained free surface coords)
    • 2: phi algebraic (non constrained nodes, on neumann boundaries)
    • 3: phi differential (non constrained nodes on dirichlet pressure boundaries / free surface)
    • 4: dphi/dn algebraic (on boat or inflow coming from L2 projection)
    • 5: dphi/dn algebraic (constrained nodes)
    • 6: phi algebraic (constrained nodes)
    • 7: dphi/dn algebraic (non constrained nodes on water/pressure coming from BEM solution)
    • 8: X algebraic (x coordinate on free surface)
    • 9: X algebraic (y coordinate on free surface)
  • For nodes that are identified as part of the free surface (water), the vertical coordinate (Z) is marked as differential, while the horizontal coordinates (X, Y) are algebraic. This reflects the fact that the free surface's vertical motion is dictated by physics (differential equation), while horizontal movements may be constrained algebraically.
  • If a node lies on a sharp edge or transom_on_water, additional constraints apply. The presence of the transom affects the boundary conditions and hence changes whether a DoF is treated as algebraic or differential.
  • Jacobian Sparsity Pattern (jacobian_sparsity_pattern): Once the DoFs are classified, the function also initializes the jacobian_sparsity_pattern. The sparsity pattern ensures that only relevant interactions between DoFs are accounted for, improving computational performance.

Reimplemented from OdeArgument.

◆ initial_conditions()

template<int dim>
void FreeSurface< dim >::initial_conditions ( dealii::Vector< double > &  dst)

Initial conditions on free surface is set.

The following points provides the important actions of this function:

  • During FreeSurface class construction, there are various functions defined in input file such as wave shape, wave potential, normal potential gradients, inflow normal potential gradients, and wind; which are further parsed as deal.II FunctionParser.
  • initial_time is defined to 0 and this time is set to all of above mentioned parsed functions. Current time variable named time and time step size as delta_t is also defined as deal.II Point<1>.
  • Store initial wind velocity parsed from input parameter file, into dealii::Point<3> Vinf.
  • Move the num_dom.map_points()'s z-coordinate of all free surface points (including boundary edges) as per initial_wave_shape which is defined in input parameter file.
  • Calculate the geometric residual using NumericalTowingTank::evaluate_ref_surf_distances(). Using geomtric residuals geom_res, we update the map_points.
  • If boat is present with transom, we perform the transom handling;
    • Store the wind velocity at very large time (possibly for steady state) and store it in VinfTinf. Resets wind's time to the initial simulation time.
    • We calculate the transom_draft which is z-coordinate of PointCenterTransom and transom_aspect_ratio which is breadth of transom at z=0 divided by transom_draft.
    • Now calculate the Froude number, Reynolds number and compute the \(\eta_{dry}\) at infinite time using the algebraic relation given in following paper.
      Note
      Read this paper on Wet and dry transom handling or see Wet and Dry Transom Stern Treatment.
    • Now we identify the region of recirculation and calculate the spatial distribution past the local longitudinal position of the transom stern (z coordinate of underlying potential flow region).
      Todo:
      Understand how the identification of recirculation region is done.
    • This updated spatial distribution near the transom recirculating region is then fed into num_dom.initial_map_points and num_dom.map_points.
    • Update the num_dom.initial_map_points and num_dom.map_points of constrained nodes.
  • Loop over all free surface cell elements in the mesh, compute the element area using numerical quadrature and then find the diameter using that area. Find the min_diameter to store the smallest computed diameter among all free surface cells.
  • Using the deal.II FunctionParser initial_wave_potential and initial_norm_potential_grad (with time set equal to initial_time in starting of this function), we store the initial boundary conditions of phi and dphi/dn in dst vector at corresponding indices.
  • Store a copy of current eulerian vector num_dom.map_points into num_dom.initial_map_points. Also update the dst vector based on these current eulerian vector num_dom.map_points.
  • On the boat surface, the normal potential must respect the boundary condition \(\partial\phi/\partial n=-V_{\infty}*\hat{n}\). This is updated in dst vector.
  • Store maximum (x,y,z) coordinates of complete domain in max_x_coor_value, max_y_coor_value and max_z_coor_value.
  • Initial various deal.II vectors required for time integration.
  • We output the dummy solution using output_results().
  • We set the num_dom.old_map_points = num_dom.map_points. Also we set last_remesh_time, current_sol_dot and current_time to zero & current_sol = dst. Also set restart_flag = false.
  • We have to compute the transom wet surface (ref_transom_wet_surface) for reference with the new mesh.
  • We finally compute the cell areas for each cell for reference, which are needed to evaluate boat cell deformations and possibly activate smoothing. It is stored in deal.II vector ref_cell_areas with its size equal to num_dom.tria.n_active_cells().
Parameters
dstStore (x,y,z) euler displacements, potential and normal potential gradient in order. Size equal to dof_numbers.

template<int dim>
void FreeSurface< dim >::prepare_restart ( const double  t,
dealii::Vector< double > &  y,
dealii::Vector< double > &  yp,
bool  restart_flag = true 
)

Method to make sure residual is null at each (re)start of the computation.

First of all, all yp for coordinates is to be set to zero: at restarts all is idle.

  • We create different deal.II ArrayView(s), extracted from y deal.II vector. Also, we get the Vinf velocity.
  • Create a new eulerian vector full_map_points which accounts the displacement field map_points. Initialize the residual vector nodes_pos_res to zero.
  • Creates a working copy of the displacement field working_map_points = num_dom.map_points for modifications. Loops through all nodes and applies constraints using num_dom.old_map_points, to ensure only certain mesh points move:
    • Water-edge nodes: Keep x and y fixed; z also fixed only if near inflow.
    • Boat nodes (not near water): Fully frozen.
    • Other nodes (not boat/water): Fully frozen.
    • Transom nodes in water: Fully frozen.
  • If the simulation just restarted, we set blend_factor = 0.0 (prevents mesh-induced velocity spikes). Otherwise, during normal operation, the blending factor smoothly increases from 0 to 1 using a sine function over half a remeshing period. After sufficient time (≥ 0.5 * remeshing_period), blend_factor = 1.0, and the mesh smoothing is fully applied. This is a stabilization technique to prevent unrealistic motion in the free surface mesh smoothing process.
  • Now we project right-side waterline nodes onto the boat surface without smoothing, ensuring nodes stay near the hull while respecting curvature. Projection happens only in the dominant direction (x or y). Same is repeated for left side. Similar smoothing projection is done for bow and stern nodes. We ensure that twin nodes of boat and far-field edge nodes have been moved by same amount.
  • We enforce the constraints on the new geometry assigned by the DAE solver. We set num_dom.map_points = working_map_points back. We update the support points and compute the normals at nodes.
  • Calculate potential gradients using compute_potential_gradients() and store the same in deal.II Vector complete_potential_gradients. Then we loop over all the water-boat interface nodes which are on water (except transom and end nodes) and make sure the boat nodes' velocity must be parallel to boat's surface. Similar process is done for bow and stern nodes.
  • Now we create a reference cell of [-1,1]x[-1,1] in local coordinates direction. Using this we try to assemble the different mass matrix for residual of non-linear system \(F(\boldsymbol{\dot{y}}, \boldsymbol{y}, t)=0\).
    • We assemble three mass matrices, one for \(\boldsymbol{\dot{\phi}}\), one for \(\boldsymbol{\dot{\eta}}\) and one for \(\boldsymbol{\partial\phi/\partial n}\). We also store the residual for all these 3 cases.
    • We first set all the global (and local) mass matrices and rhs part to zero. Same for local and global residual vector.
    • We create two different types of local mass matrices. One is using dealii::FullMatrix<double> and other using Sacado library's forward automatic differentiation fad_double which is defined as typedef Sacado::Fad::DFad<double> fad_double. We will be using Newton solver to solve the nonlinear DAE, so using fad_double will help in computing jacobians. Similarly we create fad_double compatible local residual vectors. Again, we create different std::vector<fad_double> representing all the quantities of y and yp vector separately.
    • Now we loop over each cell, reset all the local matrices, residuals and rhs vectors to zero. We store all quantities of vector y and yp. Next we set all these variables as differentiable using Sacado function x.diff(ith, n). It treats this variable x as the i-th independent variable in a problem with n total independent variables.
    • Next we calculate the center of cell, by simply taking average of coordinates of cell corners. Note that all the following computations will be using fad_double values.
    • Now we iterate all quadrature points in a cell, we calculate the quadrature point coordinates, derivative of quantities position coordinates, potential and normal potential gradient with respect to local parameters (u,v) of the cell surface.
    • Let position vector be \(\boldsymbol{x}\). Then the derivatives \(\boldsymbol{x}_u\) and \(\boldsymbol{x}_v\) gives the tangent vector of the cell, and then normal vector at that quadrature point is computed using \(\boldsymbol{n} = \boldsymbol{x}_u \times\boldsymbol{x}_v\).
    • Using these tangent vectors \(\boldsymbol{x}_u\) and \(\boldsymbol{x}_v\), we obtain the surface gradients of phi, which will help us in obtaining the \(\nabla\phi\).
    • We obtain the grid velocity and \(\nabla\eta\). All these computations are used to obtain the \(\dot{\eta}\) and \(\dot{\phi}\) RHS from ALE kinematic and dynamic BC respectively.

ydeal.II vector which contains all the information of nodes displacement, potential, and normal potential gradients (This is same as dst in initial_conditions() method function).

◆ reinit()

template<int dim>
void FreeSurface< dim >::reinit

This function initializes and resets various degrees of freedom (DOFs), sparsity patterns, solution vectors, and residuals needed for free surface computations in a numerical domain.

  • Compute total Degrees of Freedom (DOFs): It will be sum of node positions (num_dom.vector_dh.n_dofs()), node potentials (num_dom.dh.n_dofs()), and nodes normal potential gradients (num_dom.dh.n_dofs()) in same order.
  • compute_constraints(): Sets up constraints for scalar constraints and vector vector_constraints DOFs. Here we prepare the constraint matrices so as to account for the presence of the hanging nodes.
  • Initialize Sparsity Patterns and then using deal.II DoFTools::make_sparsity_pattern() to define these sparsity patterns and finally compress sparsity patterns for efficient storage.
    • DphiDt_sparsity_pattern for mass matrix of \(\dot{\phi}\) (ALE dynamic BC)
    • vector_sparsity_pattern for obtaining the potential gradient field using phi and dphi_dn values.
  • Reinitialize various deal.II vectors:
    • working_map_points
    • nodes_pos_res
    • nodes_ref_surf_dist
    • current_sol and current_sol_dot
    • bem_phi and bem_dphi_dn for BEM-related computations.

◆ residual_and_jacobian()

template<int dim>
int FreeSurface< dim >::residual_and_jacobian ( const double  t,
dealii::Vector< double > &  dst,
const dealii::Vector< double > &  src_yy,
const dealii::Vector< double > &  src_yp 
)

This function computes the residual and Jacobian matrix for the DAE system.

  • Set the jacobian_matrix. jacobian_dot_matrix, and dst to zero.
  • Create different dealii::ArrayView(s) from src_yy and src_yp vector, to store nodes position, grid velocities, potential, normal potential gradients, and their time derivatives.
  • Set the bool new_time_step to true.
  • Set the wind and inflow_norm_potential_grad functions to the current time t.

First we start with geometric part of the variables.

  • Set the jacobian_matrix for all the constrained (hanging node dofs). One is for position dofs, and other one is for potential and normal potential gradient dofs.
  • Update the mapping of the num_dom and its support points. Also create the copy of num_dom.map_points() into working_map_points(). We enforce constraint on the new geometry assigned by the DAE solver using vector_constraints.distribute(working_map_points).
  • Set the residual of nodes' positions to zero nodes_pos_res=0.
  • For nodes that are not constrained, we set the jacobian matrix entries for nodes position.
    • For nodes that are on edge on the free surface (except on the hull), we put 1 on the matrix diagonal for x any y coordinates. For z coordinates, we put 1 only for nodes which are on inflow-water edge.
    • For nodes that are on the hull (except at hull-water edge), we put 1 on the matrix diagonal for x,y,z coordinates.
    • For nodes that are neither on water, hull, hull-water edge, we put 1 on the matrix diagonal for x,y,z coordinates.
    • For nodes that are on the transom_on_water, we put 1 on the matrix diagonal for x,y,z coordinates.
  • Calculate the blend_factor.
  • Now we iterate over all the water-hull edge nodes and find the residual for them and populate the jacobian matrix.
    • First we consider the right water line nodes. Start with IGES surface normal. If the normal is within 30° of the y-axis (i.e. pointing mostly along y), make x-component 0 → constrain projection to y-direction.
    • Use assigned_axis_projection_and_diff_forms() to project the point in the selected direction onto the IGES surface (hull). Now using the projected position, we compute displacement for each node. Preserve either x or y depending on the dominant direction of normal to avoid instability at sharp angles.
    • Approximate local constraint Jacobians by enforcing a tangent plane constraint using the local IGES surface normal. We simply make use of equation of tangent plane to compute jacobian entries for x and y coordinates; $$ \hat{n}_x(x-x_0) + \hat{n}_y(y-y_0) + \hat{n}_z(z-z_0) = 0 $$
    • If the node has duplicates (i.e., shared between water and boat surface), copy surface normal and curvature data to duplicates which belong to boat side for consistency.
    • For the left water line nodes, we do the same as above but with the left water line.
    • In a similar fashion, we take care of bow and stern nodes. Here, we make use of the edges_tangents to compute the jacobian entries for x and y coordinates. $$ \text{For y-z plane: } y = y_0 + \frac{dy}{dz}(z-z_0) $$ $$ \text{For x-z plane: } x = x_0 + \frac{dx}{dz}(z-z_0) $$
  • Now, we address the double nodes on the edge of free surface.
  • Lastly, we calculate nodes_pos_res as difference between the num_dom.map_points() and working_map_points(). This is the geometric residual.

Now, let's look at the BEM part of the variables.

  • First we setup the BEM part. Look at the BEMProblem class for more details. Copy phi and dphi_dn to bem_phi and bem_dphi_dn and then apply the dirichlet and neumann boundary conditions.
  • Apply a correction for transom nodes on water. Count these nodes in num_dom.other_nodes, add -1 to diagonal in the jacobian matrix for dphi/dn. Now average out the dphi_dn values over its duplicates to update the bc and add (1/number of duplicates) to the jacobian matrix for dphi/dn.
  • Solve laplace using bem using solve() and update bem_phi and bem_dphi_dn values.
  • We enforce constraints in a more strict way to the hanging nodes, the vector given back by bem has constraints imposed up to the bem GMRES tolerance
  • These bem_phi and bem_dphi_dn values are then used to obtain the residual by comparing with src_yy.

Now, we take care of the free surface boundary condition (differential) part of the variables, and the boat neumann condition variables.

  • We build a reference cell of [0x1]x[0x1] and reference deal.II triangulation object. We also create deal.II finite element, DoF handler and FEValues object.
  • We create different vectors eta_res, phi_res, dphi_dn_res, x_smoothing_res and y_smoothing_res to store the various residuals. Note that first two are a bit misleading by name. eta_res will store residual for \(\dot{\eta}\) and phi_res will store residual for \(\dot{\phi}\).
  • Obtain the free stream velocity Vinf using wind function.
  • Calculate the Froude number and reference height.
  • Create various local vectors of fad_double like coordinates, potential & normal potential gradient and their time derivaties. Also various local residual vectors of fad_double are created.
  • Local stiffness matrix, mass matrix and SUPG mass matrix are created. These matrices are not deal.II matrices, but are created using vector of vector of fad_double values.
  • Compute support points in initial configuration and store them in initial_support_points.
  • Loop over all the cells.
    • Set all the local matrices, parameter vectors and residual vectors to zero.
    • Get the dof indices of the cell in local_dof_indices.
    • We loop over all the dof indices and store the coordinates and nodes velocity in the current configuration, in coors and coors_dot. We also make sure that these values are differentiable.
    • Similar thing is done for the phi and dphi_dn values and its time derivatives.
    • Next we compute the x and y displacements of all the nodes in cell, using coors & num_dom.ref_points and storing them in x_displ and y_displ.
    • We compute the cell center by taking average of all the coordinates. Using that we compute the cell diameter.
    • We create a fad_double deal.II point for gravity vector as gg.
    • We now loop over all the quadrature points in the cell. So before that we create various vectors of fad_double to store the \(\dot{\eta}\) , \(\dot{\phi}\), fluid velocity and Jacobian times weight (JxW) values at all quadrature points for a cell.
      • Initialize and calculate the quadrature point coordinates, and the derivatives of the coordinates, normal potential gradient and potential gradient w.r.t. local parameters (u,v) of the cell surface, at quadrature point. Also initialize and compute the quadrature node velocities, free surface elevation \(\eta\), and time derivative of \(\phi\). Note that we are using fad_double values for all these variables.
      • Let position vector be \(\boldsymbol{x}\). Then the derivatives \(\boldsymbol{x}_u\) and \(\boldsymbol{x}_v\) gives the tangent vector of the cell, and then normal vector at that quadrature point is computed using \(\boldsymbol{n} = \boldsymbol{x}_u \times\boldsymbol{x}_v\).
      • Using these tangent vectors \(\boldsymbol{x}_u\) & \(\boldsymbol{x}_v\) and directional derivatives of phi along u,v, we obtain the surface gradients of phi, which will help us in obtaining the \(\nabla\phi\).
      • Using \(\boldsymbol{n}\), we compute the gradient of \(\eta\). Also we compute the grid velocity, and total fluid velocity.
      • We compute breaking wave added pressure to account any breaking waves if cell is present on free surface.
      • Now, we compute the \(\dot{\eta}\) and \(\dot{\phi}\) values using the ALE kinematic and dynamic BC respectively. We also compute wave damping pressure and add it to the \(\dot{\phi}\) if quadrature point lies in the damping region. Also pressure due to breaking wave and dry/wet transom treatment is added to it.
      • We subtract the RHS part of discretized ALE kinematic and dynamic BC to the residual of \(\dot{\eta}\) and \(\dot{\phi}\) by multiplying the \(\dot{\eta}\) and \(\dot{\phi}\) values with JxW and SUPG shape function. At the same time, we also compute the local SUPG mass matrix and local stiffness matrix which then will be mulitplied with the current corresponding values from src_yy and src_yp vectors.
      • Similarly we compute the residual for \(\partial\phi/\partial n\) using the modified ALE dynamic BC on ship hull. We also compute the local mass matrix for \(\partial\phi/\partial n\).
      • We repeat the same process for the inflow normal potential gradient and apply the neumann boundary condition.
      • Now, if the cell is not on free surface, hull wall and inflow, we we simply compute the local mass matrix.
    • Now, if the cell is on free surface;
      • We complete the local residual calculation for \(\dot{\eta}\), \(\dot{\phi}\). We also compute local x and y smoothing residuals.
      • If the node is not constrained and is not transom_on_water;
        • We add the contribution of local residuals to respective global residual vector.
