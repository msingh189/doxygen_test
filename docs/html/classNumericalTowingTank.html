◆ compute_nodes_flags()

void NumericalTowingTank::compute_nodes_flags ( )

Compute the flags for each node in the mesh, to understand nodes are present in which part of the domain.

  • Before actually computing the flags at node, it calculates various std::map, and std::set like dof_to_elems, and edge_cells.
  • flags, vector_flag, and cell_flags are std::vector of GeometryFlags, which stores the following flags of each dof:
    • none: no flags assigned
    • water, boat, walls, inflow: These flags are for surface nodes
    • near_water, near_boat, near_walls, edge, keel, near_inflow: Tells us that nodes are on different edge
    • right_side, left_side: Tells us about the position of nodes in terms of left and right side of hull body
    • transom_on_boat, transom_on_water: Transom related double node flags

void NumericalTowingTank::evaluate_ref_surf_distances ( dealii::Vector< double > &  distances,
const bool  only_surf_smoothing = false 
)

Function that computes (vectorial) distances of each node from the reference (CAD) surface. Returns zero if point is on the surface or if no reference surface is specified for the node considered.

  • First update the support points vectors and then update the vector of normals at nodes using the current geometry.
  • Store the copy of map_points in smoothing_map_points.
  • vector_constraints.distribute(smoothing_map_points): enforce constraint on the new geometry
  • Now, if input flag is only_surf_smoothing==false, we loop over all the waterline curves, then its moving_points_id, update their smoothing_map_points & their doubles and calculate the tangent vector in edge_tangents at these points. It basically takes care of bow and stern nodes.
  • Again, if only_surf_smoothing==false, we hook the boat and far field double nodes to their water twins that have been moved.
  • We perform the line smoothing of keel and transom curves. It updates the smoothing_map_points, edge_tangents, and edge_length_ratios of these double nodes.
  • If argument only_surf_smoothing==false, we perform the line smoothing of all waterline curves and update the smoothing_map_points, edge_tangents, and edge_length_ratios of all the nodes of waterline curves.
  • Again if argument only_surf_smoothing==false, we move all the nodes on water of waterlines (except transom, bow & stern nodes) of RHS of boat. direction is initialized as the normal direction of the node obtained from iges_normals[i]. The third component (z direction) is set to 0.0 to ensure projection occurs in a horizontal plane. If the normal vector is very small (< 1e-3), it may indicate an ambiguous or ill-defined normal direction. In such cases, we attempt to correct the normal using a neighboring node. We're doing this thing on the water side, but the iges_normal and iges_mean_curvature belong to the boat side, so we update from boat twins. All this procedure is repeated for left hand side of boat.
  • Again we repeat, if only_surf_smoothing==false, we hook the boat and far field double nodes to their water twins that have been moved.
  • The line treatment (smoothing and projection) part is finished here. Surface treatment starts here: before doing the smoothing, we must project all nodes on the boat surface to obtain the normals and curvatures of the surface.
  • Project all nodes on the right side of the boat surface (excluding on the waterline or keel curves) to ensure they lie correctly on the hull geometry before applying smoothing. Additionally, it computes normals and curvatures to be used in further calculations. Firs the projection is attempted with AxisProjection in mesh normal direction using node_normals. If it fails, projection is done using NormalProjection. smoothing_map_points is updated. Similar procedure is repeated for left hand side of boat's surface.
  • With all the normals and curvatures calculated, we assemble the smoothing_curvature_vector used by the surface smoothing.
  • We perform the surface smoothing using surface_smoother->update_reference() and surface_smoother->smooth(). We also update the node normals after smoothing.
  • Surface smoothing might not be effective on water free surface, so all smoothing_map_points values of free surface is updated using map_points.
  • We again repeat the procedure of projecting all nodes of hull's surface as done 2-3 steps before for both left and right hand side of boat's surface.
  • We also need to compute the normals and curvatures on the keel nodes on both sides.
  • Create a deal.II Vector<double> xyz_coordinates which will store the current coordinates based on smoothing_map_points.
  • Then apply the constraints and update the xyz_coordinates of constrained nodes. Using xyz_coordinates and ref_points of constrained nodes, update the smoothing_map_points of constrained nodes.
  • Then calculate the distances which stores the changes in map_points. So basically, distances = map_points - smoothing_map_points. This is basically a geometric residual.
  • update the node normals and put old_iges_normals = iges_normals.

◆ line_smoothers

std::vector<OpenCascade::LineSmoothing *> NumericalTowingTank::line_smoothers

It is std::vector of pointer to custom OpenCascade utility created named *LineSmoothing. Size of this vector is 7, each corresponding to following curves in order:

  • for front part of the keel
  • for left transom edge/rear part of the keel
  • for right transom edge/rear part of the keel
  • for right front water line
  • for left front water line
  • for right rear water line
  • for left rear water line
